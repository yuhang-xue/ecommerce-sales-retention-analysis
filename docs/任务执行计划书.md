# 电商销售波动与用户复购分析：任务执行计划书

版本：v1.1；编制日期：2026-11-11（北京时间）。

依据：[项目实施方案](../数据分析作品_电商销售波动与复购分析.md)。配套：[任务验收文档](任务验收文档.md)。本文件保留任务基线；本次已完成第1—10节的分析与文档交付，第11节Tableau按用户要求延后。数据下载与核验的实际结果以 `data/raw/source_manifest.json` 和 `data/数据来源与下载记录.md` 为准。

## 1. 目标与范围

使用 UCI Online Retail II，回答三个问题：销售额何时发生变化；人数、购买频次、客单价以及商品和客群分别贡献多少；客户在后续完整观察期内是否再次购买。

第一版交付可复现的 SQL/Python、质量记录、指标字典、一个 Tableau Public 经营概览和一份5—6页报告。第二版扩展波动分析与用户复购两页看板。第一版仍须完成专题拆解和复购计算，区别仅在看板页数。

不包含营销因果归因、利润测算、完整退款链路或企业实时监控。未执行的经营动作只作为验证建议。

## 2. 工具、职责与目录约定

- Python：读取原始文件、质量体检、独立数值复核、图表与导出。
- DuckDB：本地分析数据库，执行分层建表和分析 SQL；无需部署数据库服务。
- Tableau Public：连接导出文件、制作和发布看板。
- 执行者：项目作者，负责开发、记录与初验。复核者：项目作者再次独立复算或指定评审人，实际执行时填写姓名，不预设签字。

## 4. 各阶段执行要点

### 4.1 读取与质量体检

以文件实际表头为准，建立原字段到标准字段的映射，不假设官网说明中的字段名与工作簿一致。客户与商品 ID 在标准层保存为字符串，缺失保留 NULL，避免出现伪客户 `nan` 或 `12345.0`。

先检查同一发票是否跨客户、国家或异常时间，再决定订单键。两张工作表合并前核查日期重叠与跨表重复；来源标识用于追溯，不应未经核查直接加入业务订单键而拆散订单。

质量标记可以重叠；用于行数和金额核对的处理分类必须互斥且覆盖全部原始记录。重复记录缺乏证据时保留，另做去重敏感性对比。负向交易保留分类，不推断其必然具有可匹配的退款原单。

### 4.2 指标与时间口径

指标字典逐项记录定义、SQL条件、粒度、分子分母、单位、缺失处理、筛选适用范围和版本。金额采用固定精度计算，结合实际价格小数位确定精度，不能逐行提前四舍五入到分。

全量有效正向金额可以包含缺失客户 ID 的交易；客户分析和乘法分解只使用已识别客户，且金额、订单和人数来自同一范围。同时披露已识别客户正向金额／全量有效正向金额，以及对应行数覆盖率。

原始日期按源数据时间解释；没有时区证据时，不进行时区转换。以自然月为分析单位，核查每日记录和源数据覆盖，排除未完整结束的尾月。数据的最大日期不自动证明所有前序月份完整。

### 4.3 分析方法

默认采用三因素 Shapley 分解，平均6种替换顺序下的边际贡献；保留基期、本期的客户数、订单数、金额、频次与客单价，以及分解残差。若任一期间无客户或无订单，标记不可分解，不强行补零。

选择变化期间时记录依据、季节性、可比天数和覆盖率。各商品／国家／新老客分别形成完整贡献分区；Top N展示必须附“其他”以核对总额。新老客拆解针对已识别客户金额；若展示全量金额，另列“客户未知”。

复购定义为首次观测购买后第 k 个自然月再次正向购买，不是累计复购率。每位客户在同一月龄计一次；月龄0可用作队列基线，但不称为复购。未完整观察单元格保持 NULL，不能填0或混入汇总。

### 4.4 看板与报告

输出 `sales_lines.csv`、`cohort_cells.csv`、`period_contribution.csv`、`quality_summary.csv` 和指标核对文件。不同粒度的数据源先独立使用，不把队列或月度汇总物理连接到交易明细。

人数和订单使用去重计数；客单价按汇总金额除以同口径订单数计算。首次观测购买月份在 SQL 中基于完整历史固定，日期筛选只控制展示。预计算贡献仅允许选择已计算期间；队列未按国家一致定义预计算前，不开放国家筛选。

报告按“摘要—口径与质量—波动驱动—分组贡献—复购—行动与局限”组织。每条结论注明范围，每条建议包括证据、可能解释、行动及验证指标。发布说明引用 UCI、作者和许可，并注明公开历史数据个人项目。

## 5. 阶段关口与变更规则

- G1（T03结束）：质量问题已记录，业务口径可执行，才进入正式指标计算。
- G2（T06结束）：总额、贡献和队列核对通过，才编写核心结论。
- G3（T08结束）：必验项全部通过、无阻断问题，才标记第一版完成。
- G4（T09结束）：扩展验收通过后，才标记三页看板完成。

口径变化记入 `docs/口径变更记录.md`：变更编号、原因、旧新规则、受影响任务与图表、重跑结果。修复后重验相关下游；不以修改验收阈值掩盖计算差异。

## 6. 风险与处理

| 风险 | 处理动作 |
| --- | --- |
| 官网元数据与数据内容不一致 | 保存元数据快照，以原始文件实测为准，记录冲突，不据元数据跳过体检 |
| 客户缺失导致复购样本偏差 | 展示月度覆盖率，只对可识别客户下结论 |
| 大额批发交易主导变化 | 展示贡献集中度，比较保留与排除极端值结果，阈值预先记录 |
| 没有明显销售异常 | 分析增长或贡献结构，不制造销售下滑故事 |
| Tableau账号或发布环境不可用 | 保留本地工作簿与截图，将线上发布标记待验；不声称最终验收通过 |
| 工作量超出估计 | 更新进度与原因，延后第二版，保留第一版必需的分析与质量工作 |
